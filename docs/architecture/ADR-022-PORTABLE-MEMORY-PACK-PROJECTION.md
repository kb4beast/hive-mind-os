# ADR-022: Portable safe-public memory pack projection

- Status: architecture adopted for Phase 3 item 1; implementation promotion requires
  the exact-candidate delivery court
- Date: 2026-07-29
- Base: `94e67cde15fa8a75d92561384241f0419c9f589b`
- Governing records: ADR-019, ADR-021, `P3-BRAIN-PACK-001`

## Context

ADR-019 requires a deterministic, local-first Markdown projection over canonical
memory. ADR-021 supplies an inert append-only Foundation store but deliberately
does not add an Obsidian projection or alter Generation Zero.

Phase 3 item 1 is narrower than the complete cognitive layer. It must produce a
portable per-repository memory pack through a CLI and ordinary editor without
implementing HOME or domain notes, Bases, Canvas, watchers, Inbox, federation,
self-hosting, retrieval, or Obsidian support claims.

Constructing `FoundationStore` is not an acceptable read boundary because a missing
path initializes a database and the constructor configures a writable connection.
The Phase 2 memory schema also contains no released human-readable summary. Dumping
storage rows or dereferencing protected content would therefore exceed both authority
and evidence.

## Decision

Add a read-only, consistent `PublicMemorySnapshot` obtained from an existing,
self-identifying Foundation database. The reader:

- opens the exact existing file with SQLite read-only/query-only semantics;
- always uses normal read-only SQLite coordination because WAL quiescence cannot be
  inferred from a momentary missing or empty sidecar;
- performs identity, shape, schema-digest, canonical-JSON, chain, relation, outbox,
  and opportunity-key integrity checks inside one read transaction;
- returns only `safe-public` `memory-record-v1` candidates and aggregate local
  omission counts; and
- binds the snapshot to the registered repository-identity digest.

Compile a metadata-only public pack at:

```text
hive-mind/
  generated/
    README.md
    manifest.json
    records/
      memory-record/
        <sha256-of-canonical-record-id>.md
```

The generated namespace is read-only and nonauthoritative. Human notes may coexist
outside `hive-mind/generated`; no Inbox or import path exists. Full hexadecimal
filenames avoid Windows-invalid canonical IDs and do not replace canonical identity.

Projection uses the separate, opt-in command:

```text
python -m hive_mind_os.foundation.brain project \
  --store <foundation.sqlite3> \
  --repo <repository-root> \
  --tenant <tenant-id> \
  --repository-id <repository-id>

python -m hive_mind_os.foundation.brain check \
  --store <foundation.sqlite3> \
  --repo <repository-root> \
  --tenant <tenant-id> \
  --repository-id <repository-id>
```

This does not modify the existing `hive-mind` console script or its 13 frozen parser
contracts. `project` requires an authentic, scope-bound
`foundation.projection.write` authority intersection. `check` is read-only.

Seven strict Phase 3 schemas separately govern note metadata, manifest, transaction,
completion receipt, conflict receipt, successful result, and typed failure result.
They do not modify the accepted 17-schema Phase 2 catalog.

## Public/private and deterministic boundary

Only records whose storage and payload sensitivity are both `safe-public`, whose
release decision and independent decider are present, and whose release subject
digest equals the canonical payload digest are eligible. Quarantined memory is
omitted. The renderer has an explicit `memory-record-v1` metadata allowlist and never
emits `protected_content_ref` or `retrieval_receipt`.

Public bytes use UTF-8, LF, fixed ordering, JSON-quoted YAML scalars, bounded values,
stable source timestamps, and a cursor derived only from the sorted eligible record
set. Private/internal record IDs, sequence gaps, omission counts, absolute state
paths, wall-clock attempt time, leases, and expected-prior digests do not enter the
public pack.

Rendered strings are bounded, NFC-normalized, and reject control and bidirectional
override characters. Untrusted metadata appears only as quoted frontmatter or an
indented JSON code block; it never supplies a title, path, Markdown link, embed,
HTML element, or executable command.

## Publication and conflict protocol

The projector validates the complete desired tree before writing. A private ignored
state directory, `.hive-mind-projection-state/`, contains:

- a process-released cross-platform lock;
- a same-filesystem transaction journal with authority and expected-prior digests;
- staged desired bytes;
- immutable-by-convention completion receipts; and
- conflict receipts plus desired generated bytes, never copied human bytes.

The projector trusts a prior manifest for mutation only when its exact digest is
bound by a valid private completion receipt. An unreceipted exact desired tree may
be recognized without writing, but it cannot authorize a later overwrite. This
makes a cloned pack safe by default even when ignored private state is absent.

All managed file digests and the complete generated namespace are checked again
under the process lock. Pack and protected-state roots, every state subtree,
multi-linked protected-state files, and same-file database overlap are revalidated
before staging or publication. Notes are
atomically replaced from staging and `manifest.json` is published last. Restart
accepts only prior or exact desired digests, cleans stale completed transaction
state, and resumes the same transaction. An unexpected, missing, renamed, manually
edited, linked, or unowned generated path produces a whole-plan conflict: conflicting
bytes are never overwritten, desired bytes are preserved in protected state, and the
command exits nonzero.

Item 1 never deletes a prior managed file. Append-only supersession and tombstones
remain records. A future cleanup/migration command requires its own manifest-owned
exact-digest contract.

## Source and dependency disposition

No new external source or dependency is admitted. `P1SRC-OBSIDIAN-HELP` remains
`adapt` for the narrow facts that a vault uses ordinary local Markdown and ordinary
editors can read it. Its unresolved documentation-reuse terms prohibit copying help
text or templates; all emitted bytes are repository-owned. JSON Canvas and Obsidian
CLI/URI/plugin/Sync behavior are outside this item.

Phase 2 outbox acknowledgement is explicitly deferred. Historical messages use the
generic `local` destination and were not admitted as `brain-memory-pack-v1`
deliveries. Item 1 does not relabel or acknowledge them. A routed consumer requires
a versioned later migration.

## Threats and dissent

- Digest checks plus a scope lock address routine concurrent projectors and editors,
  but are not a cryptographic compare-and-swap against a malicious writer.
- Atomic file replacement is per-file; the manifest-last protocol is the commit
  marker for readers.
- SQLite always uses normal read-only coordination. It may create or use empty WAL/SHM
  sidecars but does not perform a logical canonical write.
- Public release can still expose low-entropy correlation through approved IDs and
  digests. Independent release remains mandatory.
- The Phase 2 memory record contains metadata, not a useful public prose body.
  Rich notes belong to Phase 3 item 3 after a safe-content contract.
- The public pack is not claimed complete, useful, refreshed by Obsidian, federated,
  or safe for intake.

## Migration and rollback

This is additive and opt-in. It changes no Generation Zero selector, facade, prompt,
store, schema, role behavior, package selection, or existing CLI parser.

Rollback stops invoking the module command. Preserve the canonical database,
generated pack, transaction/conflict receipts, dissent, and audit evidence. Removal
of generated files is manual unless a later exact-manifest cleanup contract is
adopted; human files and canonical state are never removed by item 1.

## Evaluation

Acceptance requires exact frozen `131/33/13/304` compatibility, deterministic clean
and repeat trees, read-only snapshot receipts, scope and release enforcement,
private/quarantine exclusion, bounds and hostile-render tests, Windows-safe paths,
manual-edit conflict preservation, interruption recovery, strict schema and drift
checks, full Python 3.11/3.12/3.14 verification, security/supply-chain receipts, and
independent Curator, Steward, and Judge reconstruction.
