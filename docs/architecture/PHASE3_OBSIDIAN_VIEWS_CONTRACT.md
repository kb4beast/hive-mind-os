# Phase 3 item 4 Obsidian views contract

## Scope and authority

Item 4 is an opt-in, nonauthoritative projection over a verified item-3 cognitive
tree. It does not read canonical/private or public SQLite persistence.

| Operation | Required authority | Mutation |
| --- | --- | --- |
| Compile/check desired views | explicit local read access | none |
| Publish views | authentic `foundation.projection.write` intersection | item-4 namespace and external item-4 protected state only |

Item-3 receipt possession, generated content, or rendering never grants authority.

## Source admission

The source must be an exact item-3 `hive-cognitive-manifest/v1` under
`hive-mind/generated-cognitive`, with:

- exact tenant, repository, identity, namespace, projector, and mapping scope;
- a complete exact ownership-receipt chain;
- every listed file present with its exact digest;
- exactly the expected six domain directories and no unmanaged path;
- no symlink, hardlink, reparse point, junction, reserved sibling, conflict drift,
  or pending item-3 transaction.

Item 4 holds the existing item-3 lock for project mode and revalidates source identity
immediately before installing the manifest commit marker. It never recovers or
repairs item 3. Cooperative item-3 writers cannot cross that lock. Mutation by an
uncooperative writer after the final pre-manifest validation remains explicit
filesystem dissent and is not claimed detected or rolled back.

## Generated artifacts

The exact file set is:

- `bases/ideas.base`;
- `bases/released-war-room.base`;
- `bases/agent-records.base`;
- `bases/telemetry-metadata.base`;
- `canvases/war-room.canvas`; and
- `manifest.json`.

Bases are strict deterministic YAML rendered from validated typed objects. Each uses
only fixed global filters, fixed property display names, one core table view, and a
fixed property order. Source-derived structure is limited to a validated
`sha256:<64hex>` repository identity digest.

The Canvas is canonical JSON using only text and file nodes with fixed labels,
integer geometry, unique domain-separated IDs, vault-relative constant paths, and no
edges.

## Truthfulness

- Ideas means released opportunity-memory metadata, not quality, priority, value, or
  uniqueness.
- War Room means a released static metadata view, not live state, readiness,
  urgency, causality, or authority.
- Agent records are social-memory metadata, not definitions, scores, health,
  performance, rank, or fitness.
- Telemetry is evaluation/resource metadata; token, cost, provider, invoice, value,
  ROI, and effectiveness accounting are unavailable. Unknown is not zero.
- Loop state is unavailable because the source exposes no loop signal.
- Quarantine inventory is unavailable because item 3 admits only nonquarantined
  safe-public memory. No all-clear or zero claim is permitted.
- Court notes are metadata, not Judge verdicts.

No loop or quarantine Base is emitted.

## Safety and determinism

Generated bytes are UTF-8 without BOM, LF-only, fixed-order, and final-newline
terminated. Untrusted source strings never enter YAML expressions, Canvas text,
paths, node roles, or geometry.

The projector rejects path traversal, absolute paths, URLs, links, embeds, HTML,
scripts, plugin functions, dynamic time, file timestamps, aliases, custom YAML tags,
and unsupported object keys.

Stable node IDs exclude source cursor, timestamps, mutable state, display text,
geometry, and publication attempt. Base/Canvas bytes remain stable across item-3
cursor changes for the same repository identity; the manifest records the current
source cursor and manifest digest.

## Publication

Item 4 uses its own disjoint protected root and namespace. Exact source verification
precedes compilation. Publication is bounded, journaled, manifest-last, restartable,
and no-overwrite. Exact prior ownership is required for updates. Manual edits,
unmanaged paths, missing paths, links, late writers, forged journals, corrupt staged
bytes, and corrupt receipts fail closed with typed evidence.

Check mode creates no file, directory, lock, journal, receipt, or conflict.
Every protected receipt and conflict record is validated, and every receipt must be
reachable from the installed manifest head after recovery. Unrelated forged evidence
is not admitted. Append-only receipt history is iteratively bounded at 200,100
protected paths; pending transactions are separately bounded at 64 and conflict
evidence summarizes overflow after 200 paths.

Fresh publication writes the canonical journal before staging desired bytes in a
preparation directory. Only an exact complete preparation is atomically renamed into
the sealed transaction set. Incomplete preparation bytes are moved, never discarded,
to content-addressed abandonment evidence. Its canonical receipt binds the original
transaction ID, exact relative paths, and file digests; every receipt/evidence pair
is revalidated on admission. Preserved file paths are limited to
`transaction.json` and `files/<64hex>` under the single allowed `files` directory.
When a canonical journal exists, its transaction ID must equal the abandonment
receipt's transaction ID. Invalid preparation shapes fail closed in place rather
than producing evidence that the next run would reject.

Recovery accepts a current authentic `foundation.projection.write` decision only for
the journal's exact tenant and repository. The journal's original decision, actor,
and lease remain immutable historical evidence but are not required to still be the
active lease after restart. A verified hardlink install interrupted between
destination creation and next-file removal is completed only when both names are the
same file with the exact desired digest.

The item-3 transaction root must itself be a real unlinked directory before it is
enumerated. Within a validation run, prior source receipt-chain nodes already proven
from an authenticated head may be cached; each journal's direct source receipt,
scope, cursor, and digest are still revalidated. This keeps validation linear in the
admitted receipt graph rather than repeatedly traversing the same history.

Final view receipts, conflict records, and abandonment receipts use a fully fsynced
content-addressed temporary plus native atomic no-replace rename. Restart installs a
complete digest-matching temporary or discards an incomplete unsealed temporary
before replay; it never admits partial bytes at the final evidence name. Check mode
does not recover the temporary. Installing a completed receipt and cleaning its
sealed transaction is reported truthfully as `recovery_status=recovered`. Directory
seals use the same no-replace primitive.
Supported primitives are Windows rename-without-replace, Linux `renameat2`, and
macOS `renamex_np`; other platforms fail closed.

`cognitive-view-abandonment` is an internal canonical protected-state record kind,
not a ninth packaged/public schema. Its grammar and semantic checks are owned by this
module; the separately installed contract catalog remains exactly eight schemas.
On Windows the absolute item-4 protected-state root must be at most 110 characters,
leaving the deepest `preparations/<64hex>/files/<64hex>` path at most 259
characters. A longer root fails before any item-4 mutation.

## Compatibility boundary

The output implements a repository-owned strict subset of the pinned official Bases
syntax and JSON Canvas 1.0. It does not claim a numbered Base format, runtime
rendering, automatic refresh, or Obsidian support.

Frozen `131/33/13/304` surfaces and prior `17/7/3/8` schema catalogs remain exact.
Item 4 has a separate eight-schema catalog and module command.
