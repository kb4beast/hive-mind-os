## Compatibility surfaces

The inventory separates compatibility promises from observable
implementation details.

| Classification | Surface | Generation-zero receipt |
| --- | --- | --- |
| supported | `hive_mind_os.__all__` | 131 bindings, package version, callable signatures, class bases, declared public member signatures, enum values, and stable defaults |
| supported | `hive_mind_os.package_system.__all__` | 33 bindings resolved to the same deduplicated definition registry |
| supported | `hive-mind` console script | 13 semantic parser contracts with action names, options, destinations, requirements, defaults, choices, and types |
| de-facto | non-underscore top-level module definitions | 304 definitions across the source tree; inventoried for migration risk but not represented as a new support promise |
| de-facto data | public upper-case module assignments | source-expression digests retained without claiming each constant is stable API |
| data contract | schemas, package resources, roles, prompts, databases, model-call envelope, and docket | retained in fixture version 2 and the existing resource/state receipts |

A signature failure is a compatibility event. Regenerating the artifact and
fixture without a court disposition, migration, rollback, and independent
review is prohibited.

The canonical form deliberately excludes interpreter-formatted help text,
normalizes `sys.executable` defaults, canonicalizes union aliases, and derives
observable source expressions from source segments. This keeps the evidence
contract stable across the supported Python matrix without hiding semantic
parameter, default, annotation, return, option, or binding changes.

Enum metaclass construction signatures are also excluded because Python 3.11
and 3.12+ expose different interpreter internals. The supported contract is
recorded as value lookup plus the exact member names and values.

## Event path result

The AST receipt contains:

- 48 direct `EvidenceLedger.append_event` sink sites;
- 53 event-producing sites after resolving the six `ExhibitStore._event`
  wrapper calls;
- 47 unique literal production event types; and
- zero dynamic event-type candidates outside the declared wrapper.

This closes the earlier prose-only path list for generation-zero source. It
does not declare the existing event model sufficient.

Material defects preserved by the inventory include:

1. `HiveKernel.run_objective` emits lifecycle events under a generated run ID,
   while `ModelBackend._record_call` normally emits `model.call` under the
   objective ID. Those streams can be orphaned unless the caller deliberately
   makes the identities equal.
2. Scheduler mutations, mission-state mutations, successful sandbox effects,
   and direct Git/GitHub effects do not have a one-to-one transactional event
   or outbox receipt.
3. `war_room.event` and `experiment.decision` appear in tests but have no
   production emitter.
4. Source-ingestion events use the shared run ID `source-ingestion`, and some
   actor fields join multiple judge identities into one string.
5. Scheduler leases and retries overwrite current state, preventing exact
   historical reconstruction.

## Persistence and effect result

The bounded static rules record 224 call sites across:

- SQLite writes and transaction control;
- event and lesson append paths;
- filesystem create, write, replace, move, copy, delete, durability, and
  temporary-file paths;
- process and Git command boundaries; and
- network and remote-API boundaries that may persist external effects.

Every matched call site records its source path, line, column, owning symbol,
category, and sink. SQL receipts also retain statement verbs. The executable
test fails if a matched SQL statement, write mode, or event type cannot be
classified.

Important architectural defects remain:

- projection reads instantiate stores and can create directories/databases on
  an absent root;
- the evidence ledger and scheduler have no persisted migration version;
- database, prompt, evidence-file, Git, and remote effects have no cross-store
  transaction or outbox;
- PIT seals and reveal digests are process memory and cannot resume after a
  restart;
- benchmark/projection writers lack one consistent atomic-write contract; and
- append-only triggers and create-only files do not provide authenticated
  deletion or tamper resistance.

## Truth boundary

This is a machine-reproduced, bounded static characterization, not a proof
that Python or the operating system has no other side effect. Receiver aliases,
native extensions, generated code, reflection, and behavior hidden behind an
unlisted adapter require dynamic tracing. Clean-wheel parity, fault injection,
read-only no-write tracing, event-schema adoption, privacy classification,
cross-store recovery, migration, concurrency, and Windows-specific behavior
remain Phase 2 acceptance obligations.

The correct claim is: every source site matched by the published coverage
contract is registered and reproducible, and the important known gaps remain
explicit. The incorrect claim is: all runtime effects are complete, safe,
atomic, private, or replayable.
