# ADR-026: Pinned Obsidian vault refresh conformance

- Status: proposed; independent judgment pending
- Date: 2026-07-29
- Scope: Phase 3 item 5
- Depends on: ADR-019, ADR-022, ADR-023, ADR-024, ADR-025

## Decision

Propose a narrow black-box conformance claim for Obsidian Desktop `1.12.7` on the
recorded Windows host:

- an already-open item-1 README reflected an external atomic replacement;
- an already-open item-3 HOME reflected an external atomic replacement;
- an open Ideas Base recomputed after item 3 published a new idea note;
- the generated war-room Canvas rendered through core Obsidian; and
- after an unload and bounded stability interval, Obsidian leaves every generated
  Base and Canvas byte unchanged.

The test uses the real item 1–4 projectors against a disposable no-hardlink clone.
Protected stores and projector recovery state remain outside the vault. `.obsidian`
is local-only and ignored.

## Runtime-discovered repair

The first run refreshed correctly but Obsidian rewrote quoted YAML scalars in
`ideas.base`. Item 4 then reported a managed-file conflict. The failed run is
preserved.

The projector now emits YAML plain scalars only when they are unambiguous and
retains JSON-style quoting for empty, whitespace-sensitive, reserved, date/time-like,
numeric-like, or otherwise unsafe scalars.

The second run appeared to pass an immediate check, but Obsidian rewrote the Canvas
about four minutes later. That run is also preserved as failed. The Canvas renderer
now emits the exact tab-indented, compact-node form observed from Obsidian `1.12.7`.
The earlier passing run was superseded after further production hardening. The
sealed exact-commit fourth run is the promotion candidate; independent review and
judgment remain the final gate.

## Invariants

1. No production repository is opened as the test vault.
2. Only safe-public synthetic records enter screenshots.
3. The visible-refresh deadline is 15 seconds and the post-Canvas-unload stability
   interval is 300 seconds.
4. No refresh gesture, restart, cache rebuild, plugin, Sync, importer, external
   watcher, or network Git action may participate.
5. A visible refresh is insufficient if generated bytes change.
6. Runtime screenshots, the final projector receipt, observed target hashes, and
   timestamps are bound in one run evidence directory.

## Alternatives rejected

- A hand-authored note-only probe cannot prove projector integration.
- Documentation-only acceptance cannot prove versioned runtime behavior.
- A plugin or watcher would test the workaround rather than core Obsidian.
- Treating semantically equivalent Base rewrites as harmless would violate item-4
  manifest and ownership receipts.

## Consequences and limits

If independent judgment adopts it, the result closes only the item-5 local-runtime
obligation for this exact build and host. It does not activate Obsidian as an
execution host and does not prove clean-profile, remote Git, multi-device, Sync,
production-readiness, usefulness, or superiority. The test reused an already-running
Obsidian process, which remains explicit dissent.
