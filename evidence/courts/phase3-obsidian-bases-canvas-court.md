## Cross-examination and repair

The independent Cross-Examiner remanded the first runnable candidate for two critical
publication defects and high-priority provenance, race, evidence, and history gaps.
The repaired candidate now:

- validates transaction identity, staged manifest, exact desired/prior plan, source
  evidence, and staged file set before any replay mutation;
- preflights every reserved sibling, preserves mismatches byte-exact as typed
  conflicts, and uses managed-ancestry checks plus Windows no-delete leases around
  final no-overwrite hardlink installation;
- binds current and historical view receipts to exact item-3 receipt evidence;
- revalidates item-3 source immediately before manifest install under the held
  item-3 lock;
- validates measurable conflict evidence and rejects malformed existing evidence;
- validates every protected receipt/conflict and rejects receipt branches not
  reachable from the installed manifest head; and
- separates append-only history, pending-transaction, and conflict-reporting bounds.

The Cross-Examiner's recommended raw tenant/repository and note-kind filters were not
adopted. Raw identifiers are prohibited from generated expressions; exact item-3
folder ownership plus the repository-identity digest binds scope, and item-3 drift
rejects spoofed files. This remains preserved dissent pending runtime vault tests.

## Steward remand and repair

The independent Steward remanded the current-byte candidate for five recovery and
scaling defects:

1. interruption after hardlink installation left a valid two-link next/destination
   state that preflight rejected;
2. interruption before transaction sealing could leave no recoverable journal;
3. a valid sealed transaction required the expired historical authority identity
   rather than fresh authentic same-scope recovery authority;
4. the item-3 transaction root could be enumerated before its path type/link safety
   was established; and
5. repeated source/view receipt validation retraversed shared history.

The repair admits only the exact same-file/two-link desired-digest window and removes
the residual next name before continuing. Publication now uses journal-first
preparations and atomic sealing; incomplete preparations are preserved with
content-addressed canonical receipts rather than deleted. Recovery requires fresh
authentic authority for the journal tenant/repository while retaining historic
authority fields as evidence. Source transaction roots fail closed before traversal,
and already proven source-chain nodes are cached within one bounded validation run
while direct heads remain revalidated.

The Windows path-length issue exposed by the first abandonment design was separately
repaired: one 64-character content identity names both the evidence directory and
its sibling receipt, which carries the full original transaction ID and file
digests. Targeted tests cover all five remand findings, incomplete-evidence
tampering, and the path-safe preservation layout.

The Curator then remanded two abandonment-admission inconsistencies: a re-addressed
receipt could disagree with its readable preserved journal, and an unexpected
nested path could be moved into evidence that the next run rejected. The repair
binds canonical journal transaction identity to the receipt and permits only
`transaction.json`, `files/`, and `files/<64hex>`. Unexpected shapes now fail closed
in place before any abandonment receipt or move.

The Steward's renewed review then remanded partial writes directly at final evidence
names, the uncatalogued `schema_version` claim, check-then-rename directory seals,
and the unenforced Windows path budget. The repair uses content-digest temporaries
plus native atomic no-replace rename for all final evidence, recovers full
temporaries, and discards only proven-partial unsealed temporaries before replay.
The abandonment document is explicitly an internal `record_kind`, not a packaged
ninth contract. Windows, Linux, and macOS no-replace primitives are selected
explicitly; unsupported systems fail closed. Windows protected-state roots longer
than 110 characters fail before mutation.

New regressions interrupt writes inside completion, conflict, and abandonment
evidence; inject a late destination directory at the seal boundary; and exercise the
Windows 110/111-character boundary.

The final Curator full-temporary reproduction found one reporting defect: restart
installed a complete completion-receipt temporary and cleaned its transaction but
returned `recovery_status=not-required`. Recovery now carries the installed receipt
through completed-transaction cleanup and reports `projected/recovered`. A dedicated
regression interrupts after full fsync but before the no-replace install.
