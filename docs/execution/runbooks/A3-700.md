## 1. Contract summary

**Objective.** Qualify A3 repository autonomy on real disposable repositories
without remote delivery authority. A3 means: routine, reversible, local repository
missions complete end-to-end without discretionary human answers, and the cheating,
recovery, and rollback evidence produced along the way remains valid.

**Acceptance criteria (compressed).**
1. Multiple (>= 2) real disposable repository missions complete end-to-end.
2. No discretionary human answer is needed for routine reversible work
   (every human-shaped question is either resolved by role consultation or recorded
   as an escalation — and no escalation fires during the routine missions).
3. Cheating, recovery, and rollback evidence remains valid (verifiable receipts,
   a demonstrated tamper rejection, a demonstrated rollback).

## 3. Design — evidence tree and document

Create exactly this layout (all new files):

```
evidence/pilots/a3/
  summary.json                     # top-level pilot record (schema below)
  missions/
    mission-01-example-verify/     # copied receipt bundle from run_example.py
    mission-02-enqueue-loop/       # receipts from the enqueue/fixture mission
  cheating/tamper-rejection.json   # transcript of a mutated-candidate rejection
  recovery/rollback.json           # transcript of the rollback demonstration
  tests/                           # focused-test transcripts (stdout+exit code)
docs/execution/A3_REPOSITORY_AUTONOMY.md
```

`summary.json` schema (write it by hand; every field required):

```json
{
  "node": "A3-700",
  "base_commit": "<40-hex release-branch SHA the node branch started from>",
  "final_commit": "<40-hex node-branch head>",
  "missions": [
    {"id": "mission-01-example-verify", "repository": "disposable local path",
     "candidate": "<40-hex>", "verdict": "accepted", "receipts": ["relative paths"],
     "human_answers_required": 0}
  ],
  "cheating_evidence": "cheating/tamper-rejection.json",
  "recovery_evidence": "recovery/rollback.json",
  "rollback_reference": "git revert of <final_commit> restores base",
  "remote_delivery_performed": false,
  "changed_paths": ["evidence/pilots/a3/**", "docs/execution/A3_REPOSITORY_AUTONOMY.md"]
}
```

**Pilot procedure (the actual work).** All disposable repositories live in a temp
directory OUTSIDE the repo tree (e.g. `%TEMP%/a3-pilot/`); only their receipts are
copied into `evidence/pilots/a3/`.

*Mission 1 — example verification mission.*
`python examples/verify-an-agent-change/run_example.py --output <tmp>/a3-mission-01`.
Copy `<tmp>/a3-mission-01/receipt-bundle/verification.json` and `receipts/` into
`evidence/pilots/a3/missions/mission-01-example-verify/`. Record the candidate SHA
(`git -C <tmp>/a3-mission-01/nonprofit-checkout rev-parse HEAD`).

*Mission 2 — second, distinct disposable repository.* Build a fresh git repo in
`<tmp>/a3-mission-02` (init, commit a small Python file, commit an agent-style
change), author a minimal sealed acceptance spec modeled on
`examples/verify-an-agent-change/acceptance-spec.json`, then run
`hive-mind verify --repository <repo> --spec <spec> --candidate <sha> --output <tmp>/a3-m02-out`
(or `python -m hive_mind_os.cli verify ...` if the entry point is not installed).
The spec file itself lives in the temp dir; copy it plus `verification.json` into
`evidence/pilots/a3/missions/mission-02-enqueue-loop/`.

*Cheating evidence.* Re-run `hive-mind verify` in mission 2 with a deliberately wrong
`--candidate` (the baseline SHA instead of the change SHA, or a SHA whose worktree was
mutated after sealing). Capture the failing output and nonzero exit code into
`cheating/tamper-rejection.json` as `{"command": [...], "exit_code": N, "stderr": "..."}`.

*Recovery/rollback evidence.* In mission 2's repo run `git revert --no-edit <sha>`,
show `git status --porcelain` clean and `git rev-parse HEAD` advanced; record in
`recovery/rollback.json`.

*Human-answer accounting.* Each mission record carries `human_answers_required: 0`;
if any step genuinely requires a discretionary human answer, STOP and `autopilot fail`
(that is an acceptance failure, not something to paper over).

**Document.** `docs/execution/A3_REPOSITORY_AUTONOMY.md` (~80–150 lines): what A3
means; the two mission narratives with exact commands and SHAs; the no-remote-delivery
boundary; how to re-run the qualification; explicit statement that A3 does NOT grant
remote delivery (that is A4-800, behind the owner-credential gate) and does not touch
`HUMAN_AUTHORITY_GATES.md` decisions.
