# Disposable generic DAG fixtures

The qualification matrix constructs fresh, bounded subjects for Python,
Node/TypeScript, C sharp, Rust, a monorepo, documentation-only work, a repository
with no tests, a target-advancing candidate, offline-local data, a research
artifact, and a workflow. Files are original minimal fixture text and are deleted
with their temporary directory.

Every subject is content-addressed through the installed subject contracts, then
planned and compiled through `SubjectExecutionService`; non-repository subjects do
not gain an implicit Git identity. Repeated inspection must produce byte-identical
plans, rounds, and receipts. A representative repository plan executes only against
the disposable inert host double used by the public executor tests. The artifact
plan remains first-class for inspection and compilation, but the current V2
repository-scoped activation rejects it before any host observation or effect; a
future activation contract needs an explicit non-repository subject binding before
that execution can be authorized.

Credentials, payment, push, pull-request, comments, deployment, production, and
protected-target capabilities are absent or explicitly denied. The fixtures never
contact a live service and cannot establish external host or signing authority.
