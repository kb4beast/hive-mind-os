## Actionable findings

### R1 — P2: replay validates checkpoints individually but accepts illegal terminal transitions

Location: `src/hive_mind_os/campaign_continuity.py:466-482`, especially the consecutive-event validation at lines 473-482. `_events` validates canonical bytes, hash chaining, individual checkpoint shape, nondecreasing counters, retained candidates and immutable operation fields. It does not validate phase transitions or ensure the event kind/payload explains the state change. `_text(kind)` accepts any nonempty kind and a dictionary payload can be empty.

The independent `illegal_terminal_regression` probe first uses the public API to retain a typed `authority-denied` refusal in phase `blocked`. It then appends one canonical, correctly chained event retaining all prior events, candidate, subject, operation and attempt counters, but changing phase to `reconciling` and clearing the blocker. Reopening accepts that transition; `step` reaches `launched` and calls the in-memory adapter once. This contradicts the ADR's terminal-dispatch behavior at lines 54 and 74, and the repair's stated checkpoint phase invariants. No old history is removed or rewritten; the current prefix anchor would not reject the appended transition either.

The second probe, `success_without_receipt_payload`, appends a `reconciliation-receipt` event with an empty payload and a launched checkpoint after selection. Replay reports `launched` with zero inspections and zero launches. This is supporting evidence of the same internal event/checkpoint consistency gap: the live `_receipt` path requires an exact operation/candidate-bound authoritative STARTED receipt, but the retained representation need not contain any receipt explaining that outcome. It is not an independent claim that unsigned local records authenticate an external effect.

Scope and counterargument: these probes require the ability to write the private journal directory. A hostile authorized writer can invent an entirely self-consistent history, and the ADR explicitly excludes authenticated custody and cross-process external anchors. This finding does **not** claim to solve or bypass that excluded security model. It concerns rejecting internally inconsistent records at the validator which already promises canonical, shape, counter and phase checks and already has valid-digest malformed-state tests. The reproduced transition is structurally impossible under the public state machine and should be refused, even though a forged fully consistent history remains outside scope.

Bounded correction: validate the finite allowed predecessor/successor phase relations, terminal exceptions solely for inspection-only recovery, and event-specific state deltas. Require the retained receipt payload explaining LAUNCHED or clearing a pending effect to have the same exact typed and binding checks used during execution. Check counter increments against the corresponding intent and prevent unexplained pending/blocker changes. This can remain a local deterministic validator; no signatures, external anchor, new principal model or production adapter are requested. Add focused valid-digest tests for terminal reopening, premature LAUNCHED/empty receipt, and the legitimate blocked/exhausted recovery paths. Preserve all existing assertions.
