# Phase 3 Obsidian vault refresh contract

## Purpose

Define the smallest reproducible test that can support a local Obsidian refresh
claim without adding a plugin, watcher, importer, Sync dependency, or production
runtime component.

## Preconditions

- Pin the application version, executable/core hashes, signature, OS build, source
  commit, and a 15-second observation window.
- Use a disposable no-hardlink clone at the exact subject commit.
- Keep Foundation, public-release, cognitive, and view protected state outside the
  vault.
- Use a fresh test identity and safe-public synthetic records.
- Confirm `.obsidian/` is absent from the source repository and ignored everywhere.

## Required cases

1. Open item-1 `generated/README.md`; externally append and project; observe the
   count change in the same pane.
2. Open item-3 `generated-cognitive/HOME.md`; externally append, release, and
   project; observe the count change in the same pane.
3. Open item-4 `bases/ideas.base`; externally publish a new idea; observe Base
   recomputation in the same pane.
4. Open `canvases/war-room.canvas`; observe its disclosure text and embedded Bases.
5. Switch away from the Canvas to trigger any pending save, then keep the vault open
   for a declared 300-second stability interval.
6. Re-run item-4 check and hash every generated target after that interval. Bind
   observed per-file hashes; the manifest tree digest alone is not observed-byte
   proof.

## Verdict

- `pass`: every visible case completes inside the predeclared 15-second window,
  Canvas renders, and all projector-owned bytes remain exact after the 300-second
  post-unload interval.
- `fail`: refresh requires manual intervention, misses its deadline, the runtime
  crashes/restarts, parsing/rendering fails, or any generated byte changes.
- `defer`: the runtime cannot be pinned or the observation/isolation evidence cannot
  be captured safely.

One failed case fails the run. A repair requires a new exact-commit run; it cannot
rewrite the earlier verdict.

## Evidence

Each run must preserve:

- before/after screenshots and their hashes;
- projector completion and UI observation timestamps;
- before/after visible values and calculated latency;
- baseline and final per-target hashes, lengths, and modification times, plus the
  manifest and tree identities;
- process continuity and prohibited-action assertions; and
- a bounded claim statement.

The normative receipts are under
`evidence/phase3/obsidian-vault-refresh/`.
