The owner can receive the requested outcome through the current Plugin path: an adaptive interview, evidence-based search, transparent free/conditional classifications, and a low-noise recurrence handoff. Version 0.1.0 minimizes permissions and bias by having no publisher backend, checkout, OAuth, affiliate links, advertising, or user-profile database. ## Cross-examination and preserved dissent

The Cross-Examiner initially recommended quarantine because “any and all,” “ultimate,” service/subscription coverage, source automation, free-offer semantics, task action identity, schedule fields, public URLs, and evaluation claims were overbroad or under-evidenced. Repairs narrowed commerce scope, constrained source access, split free classifications, required exact host identities and partial-state receipts, introduced structured recurrence and semantic validation, removed superiority language, and exposed external blockers.

The Integrator demonstrated that a non-empty Watch Card alone did not prevent post-confirmation changes and found schema/validator mismatches and crash inputs. The repaired validator binds the exact pre-shown Watch Card plus every actionable setting, rejects altered digests, booleans masquerading as schema versions, malformed arrays and merchants, non-finite and impractically large numbers, invalid RFC 3339 timestamps, non-canonical or nonexistent timezones, contradictory cadence fields, and semantic free/notification errors.

The Steward demonstrated that public security reports were misrouted, stopping and quiet-hour claims were under-specified, one selector was not portable across hosts, and synthetic host failures were not public-reviewer runnable. Security reports now route privately; recurrence bounds require native host enforcement and a receipt; quiet/cadence contradictions fail closed; ChatGPT Scheduled Tasks and Codex automations are distinguished; portal cases are runnable and synthetic failures are labeled local-only.

Remaining dissent is not resolved by local tests: source coverage and authorization judgments, offer accuracy, prompt-injection resistance, same-chat duplicate suppression, and recurrence receipts are model/host behaviors. No live target-model, public-web, ChatGPT Scheduled Task, Codex automation, or notification run was executed by the independent Curator. Public policy URLs currently return 404 until merged or hosted. Publisher identity, Apps Management Write access, countries, support monitoring, name/trademark clearance, OpenAI review, and final publish consent are absent.

## Authority-repair remand and adjudication exhibit

The repair adds a digest-bound `host_payload` containing the exact surface and title, prompt-template ID, deterministic recurring-prompt content hash, and any one compound pause or resume. `coupon-hive-recurring-v1` has a golden prompt hash and canonical LF/UTF-8 renderer. A host-neutral authorized mutation plan includes the task action and ID, exact prompt bytes, type-strict structured schedule, and lifecycle list; executable comparison rejects altered, normalized, appended, mistyped, or extra dispatch fields before host-native translation.

Standalone pause, resume, and delete now use a LifecycleSpec whose confirmation is scoped to one intended call. Its fresh confirmation binds the exact host surface, returned task ID, exact title, action, observed-state precondition, expected final state, and Lifecycle Card. Immediately before dispatch, a separate host-listing observation must match and the plan is compared; a normalized receipt must then match the same action and final state. The stateless digest cannot itself prove first use, so retained host/session consumption tracking plus a new listing and confirmation are required for any retry. Unknown create outcomes cannot be blindly retried. For update plus pause/resume, an executable receipt check requires exact ID, title, surface, cadence, and timezone before the follow-up; partial success requires truthful reporting and fresh compensation authority. The legacy GPT now exports only an inert draft whose approval does not transfer to a destination host. Unicode control/format/line-separator characters and surrounding whitespace are rejected from task IDs and titles.
