## Actionable findings (complete bounded-pass batch)

1. **P1 — Bind every journal read to this controller's scope.** `_events` lines 275-296 compares checkpoint bindings only to the first journal event, while `self.scope_binding` is checked only in the constructor (245-246). An already-open controller accepts a complete valid journal restored from another scope. Because a selected/reconciling candidate bypasses the WAITING eligibility checks, it can then launch a foreign candidate using the original controller's scope. Reproduction `wrong_scope_journal_after_construction` replaced only disposable on-disk journal files: result LAUNCHED, candidate worktree `foreign-worktree` / scope digest e..., launch scope `worktree:fixture` / scope digest a.... Require current scope binding on every read, validate selected candidate against it before adapter calls, and recompute its operation binding. A wrong-scope restore should stop before observe/inspect/launch. This is a binding check, not a demand for authenticated storage.

2. **P1 — Preserve a read-only recovery route for an already-attempted launch.** `step` lines 429, 436-438 and 460-461 block before inspect when authority expires/changes or reconciliation allowance is exhausted. After launch succeeds externally but its response/persistence is lost, either condition permanently strands the outcome in BLOCKED/EXHAUSTED; all later step calls return immediately. Two reproductions show one real fixture operation and one launch, but no second inspect: expiry yields authority-expired; maximum_reconciliations=1 yields reconciliation-budget-exhausted. No new launch should be allowed after expiry/denial/exhaustion, but existing operation observation must remain possible through an explicit bounded recovery API or reserved reconciliation capacity and recoverable pending state. Do not relabel an unresolved possible effect as an ordinary terminal no-work refusal. Test lost response and failed receipt persistence on the last permitted attempt, both after expiry/revocation and at budget exhaustion. This is also required for the documented rollback handoff through the original adapter.

3. **P2 — Retain adapter-raised typed observation failures.** `_observe` lines 374-405 puts both adapter.observe and journal work in one try, then rethrows every ContinuityError. A host adapter raising ContinuityError('authority-denied', ...) therefore leaves no event or blocker; repeated steps repeat the denied call indefinitely. Reproduction: two calls, two raw exceptions, zero added events, phase WAITING. Separate the adapter-call boundary from persistence handling; retain/classify the adapter's original code and error evidence, with denial terminal for dispatch and unknown pending effects still recoverable. Journal persistence errors must remain distinguishable and must not be recursively relabeled as provider denial. Generic inspect/launch exceptions currently retain only class name; preserve safe typed codes/messages where available without assuming an exception proves absence.

4. **P2 — Strictly validate authority/launch response fields before treating them as evidence.** AuthorityObservation and LaunchReceipt have no post-init checks (186-209). `_observe` only checks observer_id truthiness and inequality, so a nonempty list passes 'observer-not-independent'. Reproduction returns observer_id=['not-an-identifier'] and reaches LAUNCHED. Validate exact nonempty trimmed observer/owner IDs, exact subject/digest/timestamp/boolean types, immutable unique reference tuples and receipt shape. LaunchReceipt.detail also needs an exact serializable text shape; arbitrary objects currently escape to asdict/JSON after a possible side effect. Retain malformed responses as typed evidence without authorizing launch; after a launch call, preserve outcome-unknown recovery semantics. Distinct labels remain structural checks, not proof of independently administered principals.

5. **P2 — Make corrupted-journal and publication cleanup failures typed and recoverable.** `_events` calls document.items before checking object shape, so canonical-looking `[]` produces raw AttributeError rather than checkpoint-corrupt; the focused reproduction confirms it. Empty/deleted journals make public methods index an empty list, and checkpoint field/state/counter/selection shapes are not validated. Validate root and nested versioned schemas and phase invariants before access. At `_append` lines 318-320, pending-file unlink occurs outside the OSError conversion: cleanup failure can mask the primary publication failure, or raise an untyped error after the event was successfully linked. Preserve the primary error and document/recover the linked-versus-unlinked outcome; do not overwrite or delete published events. Tests should exercise invalid JSON root, missing latest/all events, missing checkpoint fields, os.link failure and unlink failure after successful link, not just trailing-byte corruption or a mocked entire _append.

6. **P2 — Reject linked journal/lock files or enforce private-directory custody before touching them.** `_transaction` line 250 follows an existing .writer.lock and writes a null byte to it when empty; root.resolve also follows links and `_events` follows event links. Reproduction used an ordinary Windows hard link from .writer.lock to an empty file outside the state root: constructing the controller changed that external file to byte 00. Reject nonregular/reparse/symlink and multiply-linked mutable lock files before opening/writing; similarly prevent existing linked event files from silently redirecting journal reads. Preserve the original supplied path for checks before resolution. Trusted private directory custody reduces exploitability, as the ADR correctly says, but the current implementation neither establishes that custody nor prevents accidental linked-file collateral writes. A real host integration must supply and enforce it; do not advertise path isolation from this code alone.

## Boundary audit and non-findings

- Constructor/intake: immutable scope/candidate/delivery dataclasses validate most input domains; delivery/candidate intake is idempotent for identical documents, retains conflicts, and does not move a terminal LAUNCHED result backward. Existing selection checks exact subject/worktree/scope/authority, reversibility and disposition for WAITING candidates. Late intake and no-eligible-candidate are intentionally terminal; callers must finish their intake before stepping.
- Journal: fsync of temporary file precedes same-filesystem hard-link publication; the no-overwrite property is sound under cooperating writers. Directory fsync/power-loss durability is explicitly excluded. A hash chain alone cannot detect truncation/replacement by a writer with custody; do not add an authentication claim. Public checkpoint/events/step results are reloaded from disk and not retained as live controller state. A positive mutation control changed returned nested dictionaries and observed no persisted change.
- Observe: fresh authority is checked before selecting and again immediately before launch, including exact verified-reference set and explicit literal boolean permission. Observe exceptions, malformed values and expiry boundaries need the corrections above. The adapter remains responsible for actually resolving evidence and obtaining independent current repository/owner facts; these tests use a clearly labeled MemoryAdapter.
- Inspect/launch: reconciliation intent and attempt counters are persisted before calls; authoritative ABSENT alone permits a launch; UNKNOWN/unconfirmed absence never authorizes one; immutable operation ID binds full scope/delivery/candidate. Launch exception is conservatively outcome-unknown and ordinary restart inspection works while authority/budget remain available. Receipt substitution is detected; malformed or denied receipts can currently terminalize an uncertain external effect, covered by recovery finding 2.
- Concurrency: a focused Windows spawned-process control held observe under the transaction while a second process constructed a controller for the same root. The competitor returned writer-busy; the first completed one fixture launch; both exited 0 and final phase was LAUNCHED. This validates that specific cooperating-process exclusion, not every Windows/POSIX race, process kill, filesystem alias or adapter idempotence scenario. Holding the lock across adapter calls prevents concurrent dispatch but can block all state access if an adapter never returns.
- Deadlines: adapter calls are synchronous and have no in-module timeouts. ADR item 7 and manifest expressly leave externally supplied deadlines unverified. Treat this as an honest integration/activation blocker, not a silently implemented bounded-wall-time guarantee. A qualified opt-in release should state which host adapter contract enforces deadlines, cancellation and unknown outcomes; killing a Python thread is not a safe substitute.
- Paths/evidence: URI/digest fields are declarations; the adapter, not the library, resolves them. No Git/network/credential/promotion implementation or production entry point was found. The allowlist and priority mechanism are deterministic scope filtering, not independent judgment, measured superiority or authority expansion. Rollback is stopping the caller while retaining and reconciling journal/outcome receipts, not erasing an uncertain effect.
