Hive Mind OS

v0.7.0 · prototype

Eight specialist agents do the work. A ninth thing — the evidence layer — decides whether you should believe them. Every command, exit code, diff, and verdict lands in a tamper-evident receipt bundle you can re-check offline, long after the agent is gone.

The gap it fills

CI runs after you decide to trust the change

An agent framework orchestrates work and reports success. CI runs the tests you already had, on a branch you already accepted into your pipeline. Neither one can tell you what the agent actually ran, whether it quietly weakened a test, or whether the check that passed was written before or after the code that had to pass it. Hive Mind OS inserts a step between those two: an independent role that seals its checks first, then re-runs them against the candidate in a workspace that has never seen the author's work.

The one honest “not-evaluated”

The Curator's checklist is tri-state on purpose. Four items passed: tests-weakened, rollback-artifact-verifies, diff-confined-to-declared-scope, provenance-receipts-resolve. The fifth, introduced-code-license-declared, reports not-evaluated with the reason “no automated introduced-code license classifier is in scope”. A system that scored that as a pass would be lying in a machine-readable file.

Working unsupervised

How an agent picks up work nobody handed it

There is no dispatcher assigning tasks. A role asks the graph which nodes are ready — every node whose dependencies have completed — and claims one with a lease token. Independence is safe here not because the agents are trusted, but because five separate mechanisms make the unsafe moves impossible rather than discouraged.

Five mechanisms, not five promises
  1. Declared capability. The policy engine checks the acting role, the action, and the risk tier against the role's own contract. An action the role never declared is refused even at maximum autonomy. The Explorer is read-only by a hard-coded rule, not by convention.
  2. Token-bound leases. A worker claims a job with a lease token. If the lease expires and another worker takes over, the first worker's write raises StaleLeaseError instead of silently winning.
  3. Write-scope conflict rules. Two nodes whose write scopes overlap — by path or by directory containment — must have a dependency between them, or the graph is rejected before anything runs. Parallelism cannot produce a collision.
  4. Mandatory consultation. Scheduled work names at least two other roles to consult, capped at three rounds, and a role can never be its own consultant. Eight authority classes — credentials, legal, spend, production access, protected-branch merge, owner value choices, personal consent, external commitments — escalate to a human every time.
  5. Separation of proposal from promotion. The Optimizer turns recorded outcomes into lessons and immutable challenger variants, then returns a recommendation. It cannot replace a champion, run its own evaluation, or promote anything.

Refused at every autonomy level, including the highest

Four actions are non-delegable. There is no configuration, grant, or level that permits them — the check runs before autonomy is even consulted.

  • self_replicate_unbounded
  • mutate_mission_charter
  • mutate_policy
  • conceal_activity

Separable problems

Seven different jobs, seven different entry points

The pieces are not a single monolithic pipeline you have to adopt whole. Each command below solves one problem on its own, with its own roles and its own artifact. You can use the verifier and never run an agent; you can plan a graph and execute it elsewhere.

“An agent changed my code. Did it do what it claims?”

Point the verifier at a commit and an acceptance specification that was written before that commit. The spec must declare every path the commit touched; an undeclared file fails the check. A passing run writes a bundle, a failing one writes nothing.

curator only
hive-mind verify \
  --repository /path/to/repo \
  --spec acceptance-spec.json \
  --candidate <40-hex sha> \
  --output ./receipt-bundle

“Fix this, and prove it end to end.”

The full delivery loop: reproduce the failure, write the change on a branch, seal the checks, re-run them independently, publish a reversible bundle. Runs offline against a local repository; nothing is pushed anywhere.

explorer · builder · curator
hive-mind demo

# or, against the fixture layout:
hive-mind deliver \
  --backend fixture-demo

“What state is this repository in, provably?”

Emits a digested audit of a Git worktree — repository facts, test results, and source dockets — optionally HMAC-signed with a key that is never written into the artifact. Skipping tests marks the audit incomplete rather than passing it.

steward · curator
hive-mind audit \
  --output evidence/state.json \
  --signing-key-file KEY \
  --signing-key-id k1

“Many units of work, and they must not collide.”

Plan a bounded work DAG and read it back, event-derived. Overlapping write scopes must be ordered, fanout is capped at eight, depth and budget are bounded by the charter. The graph is rejected at plan time, not discovered at merge time.

orchestrator
hive-mind kernel plan <mission> \
  --charter charter.json \
  --fixture bugfix

hive-mind kernel graph <mission> \
  --charter charter.json --json

“Drive a long campaign in a repo — without handing over credentials.”

Autopilot records an objective in the target repository and emits a host-neutral orchestration contract: content-addressed task effects your own agent host executes inside its own approved sandbox. It never creates the tasks itself, never touches a protected branch, and fails closed if a different objective is submitted for the same request.

orchestrator · integrator
hive-mind autopilot run \
  "reduce checkout p95" \
  --repository /path/to/repo

“The machine died mid-run. Now what?”

Missions can be enqueued into a durable local SQLite scheduler with token-bound leases, bounded retries, and dead-lettering, then resumed. A worker that lost its lease cannot write over the one that took over.

steward · orchestrator
hive-mind enqueue --repository . \
  --objective "…" \
  --acceptance-spec spec.json

hive-mind serve   # drain it
hive-mind resume  # pick it back up

“Is the system actually improving, or does it just say so?”

Benchmarks and experiments compare a challenger against a sealed baseline. The Optimizer may propose an immutable challenger variant and recommend it; the promotion decision is somewhere else entirely, and a lesson with no cited evidence cannot acquire an identity.

Getting started

Sixty seconds, no network, no keys

Step one 
python -m pip install --no-deps -e .
hive-mind demo

Creates a throwaway repository with a known regression, repairs it, verifies the repair independently, and writes the bundle to ./demo-out. The output directory must not already exist — the tool will not overwrite evidence.
